# K-Trader — посібник з Custom GPT Action v1.3

## Роль
Action — канал лише для читання між K_Trader Custom GPT і API сканера K-Trader. Він не може відкривати, змінювати або скасовувати ордери.

Режими:
- **Канонічний** — Action/API доступний, `data_ready=true`; торговий висновок формується лише з результатів K-Trader.
- **Резервний пошук** — Action/API недоступний або дані не готові; публічні ринкові дані використовуються лише для `WATCHLIST ONLY`.

## Пріоритетні операції
Для запиту «знайди найкращі сетапи зараз»:
1. `getHealth` або `getScannerStatus`.
2. Якщо `data_ready=true` — `listSignals` для A/A+ `LONG`/`SHORT`.
3. `listCandidates` для ширшого відбору або якщо A/A+ немає.

Для одного активу:
1. `getAnalysis` — канонічний торговий висновок.
2. `getMarketSnapshot` — останній нормалізований ринковий стан.
3. `getCandles` — підтверджені свічки, зокрема для VSA.

## Резервна поведінка
Якщо Action недоступний, автентифікація не проходить, `data_ready=false` або канонічні OHLCV/VSA застарілі чи неповні:
- не вигадувати канонічний сигнал;
- не перетворювати веб-дані на A/A+, `LONG`/`SHORT`, Оцінку сетапу, Оцінену ймовірність, Вхід/SL/TP, ATR або підтвердження VSA;
- якщо публічних даних достатньо — виконати попередній відбір і повернути `WATCHLIST ONLY`;
- використовувати нейтральне формулювання: `За результатами попереднього відбору відібрано...`;
- не використовувати від першої особи: `я б звузив`, `я б використовував`, `я вважаю`;
- якщо даних недостатньо — прямо повідомити про це.

## Пріоритет джерел
Для **кожного кандидата**:
1. Перевірити прямий публічний API на тому самому типі ринку, який просить користувач.
2. Якщо даних немає або вони неповні — перевірити ще одного підтримуваного прямого провайдера, якщо інструмент там доступний.
3. Лише після цього дозволено агрегатор на кшталт CoinGecko.
4. У відповіді вказати, які прямі джерела реально перевірено.
5. Не заявляти про недоступність прямих даних без фактичної перевірки.

Пріоритет провайдерів: Binance, Bybit, OKX, KuCoin або інший підтримуваний K-Trader провайдер.

Якщо використано агрегатор:
- позначити дані як **агреговані**;
- не подавати їх як біржову серію конкретного провайдера;
- не змішувати з канонічною OHLCV-серією.

## Правила даних
- Action API має пріоритет над веб-пошуком для поточного OHLCV/VSA аналізу.
- Не змішувати свічкові серії різних провайдерів.
- Враховувати час та актуальність даних.
- Застарілі або неповні канонічні дані не можуть бути торговим сигналом.
- Публічні веб-дані підтримують лише попередній відбір.
- Оцінка сетапу — визначена правилами оцінка якості 0–100, а не статистична ймовірність.
- `estimated_probability` залишається `null`, доки немає каліброваної моделі.
- Канонічні Вхід/SL/TP/RR/ATR/клас не перераховувати у GPT.

## Мова відповіді
Основна мова — українська.

Англійською дозволено залишати лише:
- API-операції й технічні поля;
- тикери;
- `LONG`, `SHORT`, `NO TRADE`, `WATCHLIST ONLY`;
- `VSA`, `ATR`, `MTF`, `RR`, `OHLCV`, `SL`, `TP`;
- назви бірж і продуктів.

Обов'язкові українські відповідники в тексті користувачеві:
- Setup Score → **Оцінка сетапу**;
- Estimated Probability → **Оцінена ймовірність**;
- Entry → **Вхід**;
- 24h low/high → **24-годинний мінімум/максимум**;
- ticker/snapshot → **ринковий знімок**;
- funding → **ставка фінансування**;
- open interest → **відкритий інтерес**;
- market direction/context → **напрямок/контекст ринку**;
- watchlist → **список спостереження**;
- screening → **попередній відбір**;
- backend → **серверна частина**;
- freshness → **актуальність даних**.

Не використовувати англійські загальні слова, якщо є точний український відповідник.

## Розгортання
Production HTTPS endpoint пройшов Phase 10 live acceptance 2026-09-05:

`https://ktrader-api.duckdns.org`

Канонічний `custom_gpt/openapi.yaml` вже використовує цей origin. Для перевірки production вузла:

```sh
python scripts/phase10_action_acceptance.py --base-url https://ktrader-api.duckdns.org
```

Для іншого майбутнього вузла або тимчасового середовища deployment-specific schema можна згенерувати без зміни канонічного production файлу:

```sh
python scripts/render_custom_gpt_openapi.py --server https://REAL_HOST --output /tmp/k-trader-openapi.yaml
```

У GPT Builder використовувати `custom_gpt/SYSTEM_K_TRADER_v1_2_COMPACT.md` як активну інструкцію. Повна `SYSTEM_K_TRADER_v1_2.md` лишається розширеною канонічною політикою.

Опис GPT не повинен містити поріг ймовірності на кшталт `≥60%`.
