# Historical Replay / Signal Outcome Spec v1.1

## Purpose

Phases 11B-11C provide reproducible provider-recorded historical data, deterministic MTF replay snapshots and conservative signal-outcome tracking. They do not convert Setup Score into probability and do not claim win-rate evidence by themselves.

## Provider history contract

A history dataset is a coherent series from exactly one provider, canonical symbol and timeframe.

Rules:

- only confirmed closed candles;
- chronological and contiguous;
- UTC timestamps;
- no provider mixing or provider fallback inside a dataset;
- Decimal market values serialized as strings;
- source kind `provider`;
- SHA-256 digest over canonical candle content;
- requested bar count and actual time range recorded separately.

Schema version: `ktrader.history.v1`.

The JSONL file starts with one manifest record followed by candle records.

## Historical collection

### Single-page compatibility path

`collect_provider_history()` captures one latest provider-native page and remains available for Phase 11B compatibility.

### Deep pagination

`collect_deep_provider_history()` pages backward through the same provider with an explicit UTC end cursor.

Current provider implementations:

- Binance USD-M: `/fapi/v1/klines` with `endTime`;
- Bybit Linear: `/v5/market/kline` with `end`.

Deep collection rules:

- exact requested closed-bar depth is mandatory;
- pages are deduplicated by candle open time;
- the paging cursor must strictly move backward;
- every page must preserve provider/symbol/timeframe identity;
- the merged series must remain contiguous and closed;
- insufficient depth or unsupported pagination fails closed;
- another provider may never fill a missing historical page.

Operator single-timeframe export automatically switches to deep pagination when requested bars exceed the provider-native page capacity; `--deep` can force it explicitly.

## MTF replay bundle

Schema version: `ktrader.mtf_bundle.v1`.

A canonical bundle contains exactly:

- `1d`;
- `4h`;
- `1h`;
- `15m`;
- `5m`.

All five datasets must share:

- provider ID;
- canonical symbol;
- provider-native symbol;
- one explicit UTC `as_of` cutoff.

A bundle is invalid if any included candle closes after `as_of`.

The bundle manifest records:

- per-timeframe candle counts;
- per-timeframe history SHA-256 digests;
- bundle-level SHA-256;
- provider/symbol identity;
- `as_of`;
- schema version.

`slice_datasets_asof()` creates replay snapshots using only bars already closed by the selected cutoff. Minimum required history can be specified per timeframe. This is the canonical no-future-lookahead boundary for MTF replay data.

## MTF collection

`collect_mtf_history_bundle()` collects each canonical timeframe independently through the same provider and shared `as_of` cutoff, then creates one deterministic bundle.

Default operational depths remain aligned with the live analysis baseline:

```text
1d   250
4h   250
1h   250
15m  250
5m   300
```

Deeper research captures may request larger values without changing either schema.

Operator export:

```sh
python scripts/export_mtf_history.py \
  --provider bybit_linear \
  --symbol SUIUSDT \
  --bars-1d 500 \
  --bars-4h 1000 \
  --bars-1h 1500 \
  --bars-15m 3000 \
  --bars-5m 5000 \
  --output data/replay/bybit_linear/SUIUSDT/sample
```

The output directory contains `bundle.json` plus one versioned history JSONL file per timeframe.

## Provider-recorded regression artifacts

Real exchange captures are generated by the operator utilities from public APIs. They are not replaced by synthetic data when a live capture fails.

Normal PR CI uses deterministic mocked provider pages so repository verification is not coupled to exchange uptime, rate limits or geographic API restrictions. A real captured bundle is auditable by its per-series and bundle digests.

## Signal outcome contract

Outcome evaluation is separate from Trading Engine setup generation. It consumes a previously emitted `TradingDecision` and later confirmed candles from the same provider/symbol.

Eligible decisions require:

- side `LONG` or `SHORT`;
- confirmed Entry, Stop and Target geometry.

`NO_TRADE` and missing-geometry decisions are `NOT_ELIGIBLE` and never enter binary calibration samples.

Canonical outcome states:

- `PENDING_ENTRY`;
- `OPEN`;
- `WIN`;
- `LOSS`;
- `AMBIGUOUS`;
- `EXPIRED_NO_ENTRY`;
- `EXPIRED_OPEN`;
- `NOT_ELIGIBLE`.

## Intrabar ambiguity

OHLC candles do not prove intrabar event ordering.

Therefore:

- entry plus Stop/Target touched in the same candle -> `AMBIGUOUS`;
- after entry, Stop and Target touched in the same candle -> `AMBIGUOUS`;
- ambiguous outcomes are excluded from binary WIN/LOSS calibration samples.

No optimistic or pessimistic ordering assumption is allowed.

## Outcome R

`outcome_r` is a planned target/stop touch label, not realized broker PnL:

- target touch -> planned geometry reward/risk multiple;
- stop touch -> `-1R`;
- ambiguous/open/expired/not-eligible -> N/A.

Slippage, fees, funding and execution quality are not modeled in Phases 11B-11C.

## Horizon

The evaluator does not invent a universal holding period. `horizon_end` is explicit and optional.

A two-hour study may pass an explicit two-hour horizon without redefining canonical Trading Engine entry rules.

## Persistence

`OutcomeRepository` stores outcome observations in SQLite with deterministic `decision_id` fingerprints.

Upserts allow unresolved observations (`PENDING_ENTRY`/`OPEN`) to be replaced later by resolved observations for the same decision.

`list_binary_resolved()` exposes only `WIN`/`LOSS` records for future calibration tooling. It intentionally does not calculate a win rate or probability.

## Calibration guardrail

Before any `Estimated Probability` is introduced, a later approved phase must define at minimum:

- sufficient sample size;
- train/validation/test separation by time;
- provider/symbol/regime stratification;
- survivorship/listing bias handling;
- ambiguous and unresolved outcome policy;
- transaction-cost assumptions;
- calibration metrics and confidence intervals;
- out-of-sample validation.

Until that work is complete, `estimated_probability` remains N/A/null.
